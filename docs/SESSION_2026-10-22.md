# Session record, 2026-10-22: how this project started

A record of the conversation that created this project, so the next session starts with the same knowledge. The plan itself is
[PLAN.md](PLAN.md); this file keeps the reasoning, the sources and the order of events.

## 1. Origin
Working on Moly (F-Droid review, see 6) the founder asked for a second product: a video game built on Moly's code, a chat with philosophic
dialogue, an artificial Socrates. Moly's code is simplified (no contact detection) and its questioning principles and prompts are changed to
the Socratic method. The old repository `Nireus79/Socrates-ai` (a Python package, v0.1.1, a Socratic assistant for software projects) was
emptied and reused. The founder wants: chrome, edge, firefox extension; Windows, Linux, macOS; and an Android version without local model
support, the same versions as Moly.

## 2. What was investigated
- `Nireus79/Socrates-ai` as it was: a 211-file Python package (`socratic_system/`), tests, workflows. Cleared in commit 22a6053 (history kept).
- `Nireus79/Socrates` (proof of concept, local copy at `~/vs_projects/Socrates`): a large Python platform. The question logic is NOT in that
  repo but in the package `socratic-agents` (0.4.8), file `socratic_counselor.py`:
  - `_generate_question`: returns an existing unanswered question first; otherwise `_generate_dynamic_question` builds a prompt in
    `_build_question_prompt` (project facts, phase with focus words, context summary, last four messages, retrieved knowledge, the last five
    questions as "DO NOT REPEAT") and asks the model for one question; `_generate_static_question` is the fallback.
  - `_generate_answer_suggestions`: 3 to 5 diverse, complete-sentence starting points from different angles, numbered list parsed by line;
    fallback `_get_fallback_suggestions`. In the CLI the user triggers it with `help`, `suggestions` or `hint` and the same question is asked again.
  - Two modes: Socratic (system asks) and Direct (user asks, system answers).
  - Much else that is not needed: workflow nodes, category-targeted selection, roles, vector database, code generation, subscriptions.
- Moly (`~/vs_projects/Moly/Moly`): Go backend `moly-go/`, extension `moly-extension/`, Android `moly-mobile/` (Capacitor + embedded engine),
  `installer/`. Its CLAUDE.md lists the product rules that carry over (one question per reply, safety first, model judgement not keyword lists,
  per-user keys, privacy, scenario tests, labelled judge batteries).

## 3. Decisions of the founder
Recorded in PLAN.md section 10. In short: a game with unlockable philosophers (each with level, topics, method, asking and answering), daily
turns and suggestions, points for accurate answers, extra turns lost for answers under the bar, Socrates unlocked last for endless Socratic
conversation and allowed to give his own view; English only; name Socrates / Socrates-ai, founder's logo, package `io.github.nireus79.socrates`
under Hermes Software; memory of claims across conversations; the no-harm principle with Moly's ethical reasoning; local and cloud models
as in Moly (Android cloud only); free launch with the sponsor card, later paid extra time and suggestions; a curated set of philosophical texts.
Android timing and code sharing were left to Claude: copy of Moly first, extract shared parts later; extension and desktop before Android.

## 4. Open questions at the end of the session
PLAN.md section 14: roster and how many philosophers at launch; daily turns and suggestions; free questions or limited; the four accuracy
criteria; purchases and clock-change cheating; sync across devices; screens (points, level bar, profile); replay; period or modern voice;
Socrates' endless mode sharing memory with the game.

## 5. Working rules for this project
- Same rules as Moly's CLAUDE.md. Do not build ahead of decisions: answer, then wait for a go.
- Commit and push only when asked. Keep pushes small. Never binaries, logs, databases or keys.
- Safety scenarios and transcripts stay local and git-ignored.
- Every unfixed problem gets a root cause. Record decisions and live findings in docs.
